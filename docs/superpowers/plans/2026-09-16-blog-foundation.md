# Blog Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the first-phase Astro project foundation for the `bigbrotherwei` blog.

**Architecture:** This phase creates a source-first Astro static site at the repository root, with TypeScript config, global styling, a minimal landing page, GitHub Pages deployment workflow, and maintenance documentation. It intentionally avoids the later visual rebuild, content collections, utility tools, traffic statistics, comments, and historical migration.

**Tech Stack:** Astro, TypeScript, npm, GitHub Actions, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-16-blog-rebuild-design.zh.md`

## Global Constraints

- Do not copy or modify `hexo-theme-fluid` source code.
- Do not implement visitor statistics or online-user tracking in the first batch.
- Do not build backend-dependent tools in the first batch.
- Use `bigbrotherwei` as the visible site title and brand.
- Keep the project source-first; generated output must not be committed.
- Deploy through GitHub Actions to GitHub Pages.
- Keep this phase limited to foundation files and a minimal verifiable site.

---

## File Structure

Create these foundation files:

- `package.json`: npm scripts and project dependencies.
- `astro.config.mjs`: Astro site configuration for `https://bigbrotherwei.github.io`.
- `tsconfig.json`: strict TypeScript base using Astro's recommended config.
- `src/env.d.ts`: Astro type references.
- `src/pages/index.astro`: minimal homepage proving routing and styles work.
- `src/styles/global.css`: global tokens and base styles.
- `public/favicon.svg`: small site favicon.
- `.gitignore`: ignore dependencies, build output, and local environment files.
- `.github/workflows/deploy.yml`: GitHub Pages deploy workflow.
- `README.md`: local development, writing, and deployment notes.

Generated by dependency installation:

- `package-lock.json`: committed lockfile for reproducible GitHub Actions installs.

## Task 2: Add GitHub Pages Deployment Workflow

**Files:**
- Create: `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes npm scripts from `package.json`.
- Produces a GitHub Actions workflow named `Deploy to GitHub Pages`.

- [ ] **Step 1: Create `.github/workflows/deploy.yml`**

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repository
        uses: actions/checkout@v5

      - name: Install, build, and upload site
        uses: withastro/action@v5
        with:
          node-version: 20
          package-manager: npm

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

- [ ] **Step 2: Validate workflow syntax by inspection**

Check that:

- Workflow triggers on `main`.
- Permissions include `contents: read`, `pages: write`, and `id-token: write`.
- Build uses `withastro/action`.
- Deploy uses `actions/deploy-pages`.

- [ ] **Step 3: Commit workflow**
