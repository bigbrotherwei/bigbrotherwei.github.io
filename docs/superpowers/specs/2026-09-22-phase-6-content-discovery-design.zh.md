# 第六阶段：内容发现与项目体系设计

## 1. 阶段目标

第六阶段补齐第一版重构计划中尚未完成的内容组织能力，让访客可以按时间、标签和上下文继续浏览内容，并让项目从静态占位卡片升级为可持续维护的 Markdown 内容。

本阶段交付：

- 项目 Content Collection、项目列表和项目详情。
- 文章归档、标签总览和标签详情。
- 文章上一篇、下一篇和相关推荐。
- 项目页、关于页和文章入口的内容完善。
- 所有新增页面的响应式手绘农场暮景背景。
- 内容关系、页面契约、背景资源和完整构建校验。

Pagefind 全站搜索、RSS、Sitemap、Canonical、结构化数据和完整上线打磨属于第七阶段。本阶段不实现分类、评论、访问统计、在线人数、CMS 或后端服务。

## 2. 内容模型

新增 `projects` Content Collection，Markdown 文件位于 `src/content/projects/`。项目 slug 由文件名决定，schema 包含：

- `title`: 项目名称。
- `description`: 列表摘要和页面说明。
- `status`: `维护中`、`实验中`、`已完成` 或 `已归档`。
- `startDate`: 项目开始日期。
- `updatedDate`: 可选的最后更新日期。
- `tags`: 项目关键词，默认空数组。
- `featured`: 是否优先展示，默认 `false`。
- `order`: 同优先级项目的人工排序值。
- `repository`: 可选的代码仓库 URL。
- `website`: 可选的线上地址。
- `background`: 必填的背景注册 key。

首个项目内容为 `bigbrotherwei.github.io`，介绍博客目标、技术栈、阶段进度、维护方式和后续方向。项目正文允许普通 Markdown，不引入 MDX 或运行时组件依赖。

文章 schema 不增加分类字段。现有专题负责组织连续阅读路径，标签负责细粒度主题，归档负责时间浏览；当前内容量不需要第四套人工分类。

## 3. 内容发现模块

新增 `src/lib/content/`，将跨页面的派生规则从 Astro 页面中提取出来：

- `sortPostsByDate`：按发布日期降序排列，slug 作为稳定兜底。
- `buildArchiveGroups`：按年份降序、月份降序组织文章。
- `buildTagIndex`：汇总标签、文章数量和稳定 URL slug。
- `findAdjacentPosts`：返回更早和更新的相邻文章。
- `findRelatedPosts`：返回最多三篇相关推荐。

标签 URL 规则：文本先执行 Unicode NFKC 标准化、去除首尾空白并转小写；连续空白转为 `-`；保留汉字、字母、数字和连字符。展示仍使用首次出现的原始标签名称。两个不同标签若生成相同 slug，内容校验必须失败，避免标签页相互覆盖。

相关推荐评分：

1. 同专题加 100 分。
2. 每个共享标签加 10 分。
3. 分数相同时，较新的文章优先。
4. 当前文章、草稿以及零分文章不参与推荐。
5. 最多返回三篇。

上一篇和下一篇按全站发布时间确定。页面文案明确标注“更早一篇”和“更新一篇”，避免中文“上一篇/下一篇”的方向歧义。

## 4. 页面与导航

### 4.1 项目

`/projects/` 从 `projects` collection 渲染，排序顺序为 `featured` 优先、`order` 升序、`startDate` 降序。卡片展示状态、标签、摘要和更新时间。

`/projects/[slug]/` 渲染项目头部、外部链接、Markdown 正文和返回项目入口。外部链接使用清晰的“查看仓库”和“访问网站”文本并安全打开。

### 4.2 归档

`/archive/` 以年份和月份分组展示全部已发布文章。每项显示日期、标题、摘要和标签。没有文章时显示明确空状态，但当前种子内容必须正常形成归档。

### 4.3 标签

`/tags/` 展示按文章数量降序、标签名称稳定排序的标签列表。每个标签显示文章数量并链接到 `/tags/[slug]/`。

`/tags/[slug]/` 显示标签名称、文章数量和按时间倒序的文章列表。文章详情中的标签改为可点击链接。

标签总览和所有标签详情分别使用独立的栏目背景。标签详情是系统派生页面，不要求每个标签单独生成背景；手工维护的文章、专题和项目详情仍必须各自拥有唯一背景 key。

### 4.4 文章详情和文章入口

文章详情正文后依次展示：

- 更早一篇和更新一篇导航。
- 最多三篇相关推荐；无推荐时不渲染空容器。
- 返回文章列表、归档和标签总览的辅助入口。

`/posts/` 增加“全部文章 / 归档 / 标签”辅助导航，不把归档和标签塞入顶栏。主导航本阶段保持不变；第七阶段再加入搜索入口。

### 4.5 关于页

关于页保留现有语气，补充当前关注方向、博客构建方式、已完成能力和已知后续计划。只使用已知信息和公开 GitHub 主页，不虚构个人经历、联系方式或社交账号。

## 5. 视觉与背景

沿用原创手绘农场暮景方向：细腻手绘为主，保留轻微游戏美术纹理，不复制第三方游戏素材。

新增四组桌面和移动 WebP：

- `archive-index`：月夜车站旁的木制档案墙，表达时间线。
- `tags-index`：温室中的种子标签架，表达主题汇总。
- `tag-detail`：林间标记牌和分岔小径，供标签详情共享。
- `project-personal-blog`：湖畔工作室与发光绘图桌，供博客项目详情使用。

桌面图至少 `1600 x 900`，移动图至少 `720 x 1280`，保持文字安全区和既有文件体积限制。背景必须登记到 `src/data/backgrounds.ts` 并通过现有视觉校验。

页面内容继续使用紧凑的 8px 以内卡片、清晰层级和稳定响应式尺寸，不增加营销式大卡片、装饰渐变球或嵌套卡片。

## 6. 错误与边界处理

- 草稿不进入归档、标签、相邻文章或相关推荐。
- 标签 slug 为空、重复或冲突时构建失败并指出来源标签。
- 项目外部 URL 必须由 schema 校验为合法 URL。
- 项目背景必须存在且不能与其他手工详情页复用。
- 单篇文章时，相邻导航为空且页面不保留占位布局。
- 无共享专题或标签时，不显示相关推荐区域。
- 所有动态路径均在构建期生成，不增加运行时 404 逻辑或客户端数据请求。

## 7. 测试与验证

新增 Node 测试覆盖：

- 标签规范化、中文和英文标签、冲突检测。
- 归档的年月排序。
- 同日期文章的稳定排序。
- 相邻文章方向与边界。
- 相关推荐评分、排除当前文章和零分结果。

扩展静态校验覆盖：

- `projects` collection schema 和首个项目内容。
- `/archive/`、`/tags/`、`/tags/[slug]/`、`/projects/[slug]/` 路由契约。
- 文章详情的可点击标签、相邻导航和相关推荐。
- 新背景 key、桌面/移动资源、尺寸、体积和唯一性。
- README 的项目、标签、归档维护说明。

完成后执行 `npm run verify`、`npm run astro -- check`、`npm run build`，并在 `1440 x 900` 与 `390 x 844` 视口进行浏览器验收：页面背景、导航、长标签、空状态、键盘焦点、文本溢出和控制台错误。

## 8. 验收标准

- 项目可以通过 Markdown 新增并生成独立详情页。
- 项目首页不再包含写死的占位项目卡片。
- 访客可以按年份、月份和标签浏览文章。
- 文章标签可点击，上一篇/下一篇方向明确，相关推荐符合确定性规则。
- 草稿不会泄漏到任何派生页面。
- 新增页面拥有符合统一风格的响应式背景。
- 完整构建、自动校验和桌面/移动浏览器验收通过。
- 功能分支推送到远端并创建以 `master` 为目标的独立 PR。
