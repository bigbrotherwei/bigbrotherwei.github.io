# 第九阶段：评论与访问统计设计

## 目标与边界

在现有 Astro 静态博客上增加可参与的文章评论，以及可信地展示访问与在线数据。读者无需为浏览或查看统计登录；只有发表 Giscus 评论时需要 GitHub 授权。静态站继续由 GitHub Pages 发布，统计能力由独立的 Cloudflare Worker 和 D1 提供。

本阶段交付：文章详情页的按需加载评论、首页的全站累计 PV / 累计 UV / 当前在线人数、文章详情页的阅读量、统计服务、公开可读的隐私说明页及中文部署文档。其他页面计入全站统计，但不显示局部计数。暂不做暗色模式、管理后台、工具单项统计、评论通知、点赞或历史趋势图。

成功标准：评论在完成 GitHub 配置后能对应到正确文章；访问统计与页面导航一致；多标签页在线去重；接口不可用时不显示假零值；未完成外部配置时博客仍可正常阅读和构建。

## 技术选择

1. **Giscus + GitHub Discussions**：评论托管于公开仓库的 Discussions。以文章 `pathname` 严格映射，文章标题修改不影响评论归属；文章路径变更需要迁移对应 Discussion。评论区仅在读者点击“加载评论”后插入脚本。相比自建评论服务，维护和审核成本低，但读者发表内容需 GitHub 账号。
2. **一个 Worker + 一个 D1 数据库**：Worker 负责接收访问、心跳和读取统计，D1 负责持久化计数、去重和在线状态。相比仅用浏览器计数可跨设备汇总；相比 KV，D1 更适合这类去重与聚合查询。Cloudflare 额度、限流和服务可用性仍是外部依赖，不承诺绝对准确。
3. **浏览器随机标识**：首次访问生成随机 UUID 存在 `localStorage`。Worker 使用服务端密钥计算 HMAC-SHA-256 后才写入 D1；原始标识不写库，也不记录明文 IP、GitHub 身份、User-Agent 或页面来源。此标识属于可关联同一浏览器访问的伪匿名数据，不称作完全匿名。

## 页面与组件

- 公共布局挂载轻量客户端统计控制器：生产站的每次页面导航发送一次访问请求；可见时立即发送心跳并每 30 秒续约，隐藏时停止定时器，重新可见时立即续约。多个标签页使用同一浏览器标识，因此在线人数按浏览器去重。
- 首页在首屏之后、内容入口之前放一行克制的统计信息，分别标注“总访问”“访客”“当前在线”，不使用悬浮卡片或遮挡手绘背景。加载中显示占位状态；不可用时显示“暂不可用”。
- 文章标题下的元信息区域显示“阅读量”，不与标签、目录、阅读进度混用视觉符号。文章正文、推荐文章之后加入评论区，点击“加载评论”才请求 Giscus。未配置 Giscus 时隐藏加载按钮并给出明确的未开放状态。
- 新增简短的 `/privacy/` 页面，说明浏览器标识、累计去重记录、在线窗口、第三方评论及清除本地标识的影响；首页统计区和文章评论区均提供可访问的链接。
- 统计和评论区不纳入 Pagefind 正文索引，也不参与文章结构化数据。窄屏保持单列、不让数字或提示文字溢出。

## 统计口径和数据流

- **PV**：一次有效页面导航记一次。刷新页面可再次计数；心跳和读取统计不增加 PV。当前版本不尝试识别真实人类或完全消除机器人流量。
- **文章阅读量**：进入 `/posts/{slug}/` 的有效导航计一次；文章列表、专题、首页等不增加该文章阅读量。
- **累计 UV**：第一次出现的浏览器标识计一位；同一浏览器重复访问不再增加。清理浏览器存储、换浏览器或设备会被视为新访客。为维持“累计”口径，D1 长期保存 HMAC 后的去重记录；用户可清理本地标识，但已累计的历史数字不会被追溯扣除。更换 HMAC 密钥也会使旧访客被重新计数，因此密钥轮换需作为一次统计口径变更记录。隐私页明确说明这些限制。
- **当前在线**：最近 90 秒内有可见页面心跳的不同浏览器标识数。关闭或隐藏页面后可能继续显示至 90 秒窗口结束；这不是实时连接数。
- 所有页面通过 `POST /visit` 上报 `{ path, visitorId }`。Worker 校验请求后在 D1 事务性批处理中更新全站 PV、可选文章 PV、全站 UV 去重记录和在线时间。页面随后通过 `GET /stats?path=...` 读取所需数字；首页读取全站指标，文章页只读取阅读量。`POST /heartbeat` 接收 `{ visitorId }` 并更新时间，不改变 PV / UV。
- D1 使用全站及文章聚合计数表、访客去重表和在线状态表。在线表以哈希标识为主键，`last_seen` 建索引；定时任务清理超过 24 小时的在线记录，读取时仍只计算最近 90 秒。所有 SQL 使用参数绑定。部署时以版本化迁移建立表和索引。

## 安全、隐私与失败处理

- Worker 仅允许配置的博客生产源及本地开发源跨域调用，处理 `OPTIONS` 预检；不设置凭据型 CORS。Origin 限制只是浏览器侧边界，不能被当作防刷保证。
- 写接口仅接受 JSON，限制请求体大小、字段长度和路径形式；路径规范化为站内 pathname，不接收完整 URL、查询参数或任意外站路径。文章路径限定为 `/posts/{slug}/` 形式；第一版只验证路由格式，不远程核对页面是否真实存在，因此可能被伪造的合法格式路径污染。对同一标识和路径在 5 秒内的重复请求去重，降低网络重试产生的重复 PV；刷新超过窗口仍正常计数。
- Worker 密钥仅以 Cloudflare secret 配置，绝不进入客户端代码、仓库或日志。公开的 Worker URL、Giscus 仓库/分类 ID 可作为构建配置。客户端标识只发送到 Worker，不传给 Giscus。
- 接口响应仅返回非负整数计数，不暴露单个访客记录、哈希值或在线明细。网络错误、D1 错误或额度耗尽时，Worker 返回明确错误，前端显示“暂不可用”；访问上报失败不阻断页面阅读，也不虚构成功或零值。
- 第三方 Giscus 脚本必须经用户点击才加载；评论区旁提示将连接 GitHub 服务。加载失败时保留重试按钮及前往仓库 Discussions 的链接。作者在 GitHub Discussions 审核评论。文章内不嵌入评论者的访问标识。
- 不承诺严格防刷或精确识别自然人。若后续遭遇明显滥用，优先启用 Cloudflare 平台限流并观察成本，再评估更复杂的防护。

## 配置与发布

- 仓库中纳入 Worker 源码、D1 迁移、示例配置、单元/集成测试以及中文配置说明；真实 D1 database ID、HMAC 密钥和部署凭据由站长在 Cloudflare 配置，不提交到 Git。
- Astro 构建读取公开的统计服务 URL；未配置时不发送统计请求并清楚标记“统计未开放”。Giscus 使用公开的仓库 ID 与 Discussion 分类 ID；未配置时不注入外部脚本。
- GitHub Pages 的现有部署 workflow 继续只负责静态站。Worker/D1 是单独的部署步骤，先创建数据库并运行迁移，再设置密钥、允许的生产 Origin 并发布 Worker，最后配置站点的公开 URL 和 Giscus 参数。第一版采用手动部署并在文档给出回滚步骤，避免在缺少 Cloudflare 凭据时破坏现有 Pages 发布。
- 用户需在目标公开 GitHub 仓库开启 Discussions、创建评论分类并安装 Giscus GitHub App。开发侧不能从代码提交中替用户完成这些账号授权步骤。

## 验证与验收

- Worker 测试覆盖路径与请求体验证、CORS、首次/重复访客、PV 与文章 PV、重复请求窗口、多标签页去重、90 秒在线边界、D1 异常返回。使用本地 D1 迁移和测试库，不依赖生产数据。
- 前端测试覆盖未配置、加载中、正常数字、服务故障、评论点击前不加载脚本、文章路径映射。运行现有 `astro check`、构建及仓库校验脚本，检查首页与文章页桌面/移动端布局。
- 上线后由站长验证：从两个浏览器访问首页、刷新文章、切换可见状态、等待在线过期；在文章评论区点击加载并发表测试评论；确认对应 GitHub Discussion、Pages 页面和 Worker 指标。出现问题可先撤回站点公开配置/停用 Worker，静态内容不受影响。
