# 第十二阶段：文章创作与阅读体验

## 目标

让作者在保留现有 Markdown 发布流程的同时，有一条可选择的富内容写作路径；让读者更容易阅读代码和图片；让常见发布错误在 PR 构建时暴露。本阶段同时修正上一阶段 Markdown 预览工具的拥挤布局和双栏滚动体验。继续使用 Astro 静态构建及 GitHub Pages，不新增账号、CMS、上传服务或运行时后端。

## 内容格式与兼容

- 现有 `.md` 文章保持原有 URL、frontmatter 字段、专题/标签/搜索/RSS/SEO 行为，不要求迁移。
- 为 `posts` 内容集合增加 `.mdx` 支持，沿用同一套 schema、草稿过滤、排序和详情页。`.mdx` 是可选格式，适用于确有交互或复用组件需求的文章。
- 同名 `.md` 与 `.mdx` 不能同时发布到同一个 slug；构建校验应给出明确错误。
- 文章组件由本地代码提供，不允许访客提交或执行任意脚本。文档分别给出普通 Markdown 和 MDX 示例。

## 可复用阅读组件

首批提供提示框、图片画廊和折叠示例三类组件。提示框使用有限的语义类型（说明、提示、注意）而不是任意颜色；画廊要求每张图片有替代文本，在桌面和手机端自动排布；折叠示例使用原生可访问的展开结构。组件须兼容明暗主题和现有文章宽度，不改变现有文章背景方案。

文章正文中的代码块提供复制按钮及成功/失败反馈；正文图片可点开查看原图并通过 Escape、关闭按钮和焦点返回退出。图片放大不能覆盖目录或永久锁定页面；无 JavaScript 时图片仍可直接查看，系统偏好减少动态效果时不播放过渡动画。页面只为存在相应内容的文章加载必要脚本。

## 发布前检查与写作指南

- 检查文章所属专题存在、专题内 `order` 不冲突、公开文章 slug 唯一、草稿不会进入公开产物。
- 检查本地正文图片/视频路径存在，图片有非空替代文本；远程链接不做网络抓取，只检查站内绝对路径可解析。页面背景继续沿用现有注册表与独立桌面/手机资源校验。
- 校验错误应指出文章文件和问题位置或字段，供作者在 PR 中修复。不要将外部链接暂时不可用视为构建失败。
- 更新中文写作指南：`.md` 与 `.mdx` 的选择、组件用法、媒体保存位置、草稿到发布的检查步骤。提供一篇示例文章用于验收，不虚构作者个人经历。

## Markdown 预览工具修正

- 仅为 `/tools/markdown/` 扩大工作区最大宽度，桌面双栏等宽，输入和预览拥有一致的可视高度、顶部对齐和独立滚动区域。避免扩大其它工具页。
- 默认启用双向同步滚动：拖动任意一侧的滚动条或滚轮时，另一侧按照各自可滚动高度的比例跟随；设置滚动位置时避免事件回环。编辑导致预览重排后维持相近的阅读位置。
- 窄屏改为纵向排列，两栏可分别滚动，不强制跨越较远距离联动；若用户启用“减少动态效果”，滚动同步仍可用，但不做平滑动画。
- 输入超过既有 1 MiB 限额、导入文件失败、清空内容时，保持现有明确反馈和安全清理行为。Markdown 渲染的 HTML 清理策略不因布局改动而放宽。

## 验收

- 自动测试覆盖 Markdown/MDX 并存、slug 冲突、文章路径/替代文本/排序错误、组件关键结构与交互、预览同步滚动边界和回环保护。
- 运行完整站点构建及生产产物校验；检查文章、专题、搜索、RSS 和 SEO 不回退。
- 桌面与手机端分别验收一篇现有 `.md` 和一篇 `.mdx` 示例文章的明暗主题、键盘操作、图片查看、代码复制；Markdown 预览工具重点验收不同长度内容的对齐和双向拖动。

## 本阶段不做

不做在线写作后台、内容上传服务、自动生成作者内容、通用自定义组件市场、自动抓取远程图片或精确到 Markdown 源码行的滚动映射。评论和统计的外部服务启用可独立进行。
