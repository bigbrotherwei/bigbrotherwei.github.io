# 第十一阶段：实用工具第二批与深色阅读配色

## 目标与范围

在现有 Astro 静态博客的 `/tools/` 工具箱中增加四个可长期使用的浏览器端工具：图片合并 PDF、Markdown 预览、文本差异对比、正则测试。同时将第十阶段深色主题的淡绿色阅读底色与面板改为炭灰、暖灰色调，保留各页原创手绘夜景、浅色主题及三态主题选择行为。本阶段使用一个功能分支和 PR 交付，不依赖新服务端、账号或文件上传。

用户已确认四个工具的范围、图片 PDF 的默认排版，以及炭灰底色、暖灰面板、少量珊瑚色和金色强调的方向。实现仍需按仓库既有工具注册、页面布局、可访问状态和 GitHub Pages 构建约束推进。

## 选择的实现路线

- 推荐路线：继续使用每个工具独立 Astro 路由、`ToolLayout`、工具注册表、共享工具样式和浏览器端脚本。PDF 使用成熟的浏览器 PDF 库；Markdown 使用成熟解析器并清理 HTML；文本差异使用成熟 diff 库；正则在专用 Web Worker 中运行。这样和现有工具一致，并能保持 GitHub Pages 纯静态发布。
- 未选路线：调用在线转换 API。它会上传用户图片/文本，引入隐私、费用和服务可用性问题，不符合工具箱现有定位。
- 未选路线：PDF、Markdown、diff 全部手写底层逻辑。文件格式和解析边界多，维护与正确性成本不合理。浏览器原生打印也难以稳定保证多图顺序、分页与下载文件名。

## 工具入口与通用交互

四个工具均加入 `src/data/tools.ts` 注册表和 `/tools/` 搜索/分类筛选；工具数量与静态路由校验不再写死为六个。图片合并 PDF 归入新增“文件”类，其余工具分别归入“文本”或“开发”类。每页延续当前 `ToolLayout` 的标题、返回入口、统一状态区域、表单与按钮视觉，并具有专属桌面和移动端手绘夜景背景。工具与背景的对应关系由注册表和背景清单测试校验。

所有输入只在当前浏览器标签内处理，不自动持久化，不发送到博客、统计 Worker 或第三方转换服务。清空与离开页面释放预览对象 URL；处理期间禁用重复执行并显示进度/结果；错误提示说明具体原因，不能只显示“失败”。手机端采用单列布局和可触达控件，键盘可完成上传、排序、切换模式、执行和下载。动态预览与状态遵守 `prefers-reduced-motion`。

## 图片合并 PDF

支持一次选择多张文件或拖入文件，首批接受 JPEG、PNG、WebP；不支持 HEIC、SVG、GIF 或已有 PDF，拒绝时列出对应文件名和支持格式。选择后显示缩略图、文件名、尺寸/大小，提供上移、下移和移除操作；顺序就是 PDF 页序。生成前可选择文件名，默认 `images.pdf`。每张图片一页，默认 A4，依据图片宽高自动横竖版；图片等比置入页内并留 24 pt 边距，不裁切。PNG 透明区在白色页上合成；WebP 在浏览器内转换为 PDF 库支持的图像格式。下载为单个 PDF，不自动上传或保存原图。

初版限制为最多 20 张、每张不超过 20 MiB、总输入不超过 100 MiB、单张像素不超过 30 MP。页面在选择时先做类型和大小校验，解码后做尺寸校验；逐张处理、按 A4 约 200 DPI 的上限缩放，避免直接把超大相机原图全部解码后长期留在内存。生成失败保留原队列供用户调整重试，完成/清空后释放临时资源。PDF 页数、顺序、宽高方向、等比留白以及输出可解析性要有自动测试。

## Markdown 预览

输入区与预览区在宽屏并列、窄屏上下排列。支持粘贴/键入与打开本地 `.md` 文件；默认输入一段简短示例，输入上限 1 MiB。预览标题、段落、列表、表格、引用、代码块、链接与图片。解析后必须清理 HTML，禁止脚本、事件属性与危险 URL；预览中外链使用安全的打开方式。图片链接可能导致浏览器向其地址发出请求，因此页面明确标明这一点；本地 Markdown 文件本身不上传。解析错误时保留原文并报告错误；输入更新做约 200 ms 防抖。

## 文本差异对比

两个明确标注的输入区分别放旧文本与新文本；支持按行和按词两种模式，结果区以新增、删除、未变的视觉和文字标识呈现，不能仅靠颜色区分。可交换两份文本、清空、复制纯文本差异摘要。每份输入最多 100,000 个字符，差异运算设置 1 秒超时；空输入和完全相同文本有清楚的结果状态。输出通过文本节点构造，不把原文作为 HTML 插入。

## 正则测试

提供表达式、常用标志位（`g`、`i`、`m`、`s`）和测试文本，显示匹配数量、位置、匹配片段及捕获组；结果文本以安全的文本节点呈现。语法错误在执行前解释；运行在专用 Web Worker，执行超过 1 秒即终止并重建 Worker，避免回溯表达式阻塞页面。匹配数上限为 1000，正确推进零长度全局匹配，防止无限循环。表达式最多 500 个字符，测试文本最多 100,000 个字符；超限或超时提示如何缩小输入。支持清空和复制结果。

## 深色主题与视觉

仅修改深色主题的语义色 token 及确有必要的局部对比度，不改主题持久化、系统跟随、导航交互和夜景图片。目标底色为接近 `#1b1d22` 的中性炭灰，面板为较亮暖灰，文字为暖白，次级文字保持足够对比；珊瑚色用于强调、金色用于焦点或夜景关联。避免淡绿色、整页单一深蓝和大面积紫色。浅色主题不变。正文、链接、输入、代码、卡片、工具、评论与统计区域在桌面/手机端都检查；普通文本至少达到 4.5:1，焦点边框至少 3:1。手绘背景仍提供每个工具独立的桌面/移动版本，并确保文字不直接压在复杂画面上。

## 测试与发布验收

- 逻辑单测覆盖 PDF 文件校验与排版、Markdown XSS 样例、差异模式、正则语法/零宽匹配/超时；浏览器测试覆盖上传排序删除下载、不同工具的键盘与窄屏交互。
- 工具注册表、页面契约、背景文件、搜索索引和生产产物校验随四个新路由更新；构建需保持 GitHub Pages 静态输出。
- 回归检查第十阶段的主题切换与现有六个工具；桌面和手机端分别检查浅色、深色，重点验证新的炭灰色调与背景、焦点可见性。
- PR 阶段运行完整构建与测试。合并后检查四个工具路由和 PDF 下载；实际大图片文件因浏览器内存差异做手动验收。此阶段不包含 Mermaid、服务端转换、OCR、PDF 编辑或批量压缩。
