# 第十阶段：主题与阅读体验设计

日期：2026-09-29

## 目标与边界

完成原重构方案中尚未实现的明暗主题能力，使读者在首页、文章、专题、搜索和工具页都能稳定阅读。保留每页现有的原创手绘夜景图片、场景布局和环境动效；本阶段切换的是前景表面、文字、边框、表单、代码块和交互状态，不新增一套白天背景，也不重做页面信息架构。第九阶段的 Cloudflare/Giscus 账号启用属于独立部署事项，不阻塞主题开发。

不增加额外跟踪服务或远端偏好账号。选择仅保存在当前浏览器。尊重系统的减少动态效果设置，且不借主题切换修改既有动效速度。

## 交互

- 导航中加入紧凑的主题按钮，使用已有 Lucide 图标并有可见焦点、名称和提示。打开后提供“跟随系统 / 浅色 / 深色”三项选择；用选中态与 `aria-checked` 明确当前偏好。移动端控制仍可通过键盘和触屏操作，不挤占导航链接。
- 初次访问默认“跟随系统”。用户明确选择后写入 `localStorage`；存储被禁用时，本页切换仍应有效。重新打开页面时恢复偏好。
- “跟随系统”状态在系统外观变化时实时更新。人工浅色或深色选择不随系统变化。
- 在首帧渲染前读取偏好并设置 `<html data-theme>`，避免页面先亮后暗。错误值回退到跟随系统；浏览器不支持存储或媒体查询时安全回退。
- 主题控制不参与 Pagefind 索引，切换不改变 URL、内容或统计计数。跨普通页面导航保持一致。

## 视觉规则

- 现有浅色阅读层是新浅色基线：浅纸色正文面板与工具工作区、深色正文和清晰的边界。深色模式使用深墨绿/炭色表面与偏暖浅色文字，不做纯黑页面或单色蓝灰皮肤。暖金、珊瑚和青绿保持节制点缀。
- 首页首屏、页头标题和夜景背景上的文字继续使用独立的浅色“景上文字”变量，不随阅读层变成深字；背景遮罩可按主题微调以维持可读性，但不替换图片。
- 将组件实际使用的前景语义归为 token：页面/面板表面、正文、次级字、边框、输入背景、强调色、状态色、阴影、代码背景及焦点圈。把硬编码颜色逐步迁移到语义 token；农场插画专用调色常量不强制重命名。
- 所有控件在浅/深模式下都需要可辨认的 hover、focus、disabled、error 和 active 状态。避免用透明度单独表达状态。
- 文章正文、目录、标签、搜索结果、工具输入输出和统计区优先检查对比度；正文与重要控件目标达到 WCAG AA 对比要求。桌面和手机视口均检查文字不溢出、组件不重叠。
- Giscus 只有读者点击后才加载；加载时使用当前有效主题，随后切换时通过其消息接口同步外观，不重新加载评论或丢失输入。

## 代码结构

1. `src/lib/theme.ts` 维护三态偏好与有效主题的纯函数，便于边界测试。
2. `src/scripts/theme.ts` 负责浏览器存储、系统外观监听、DOM 状态和导航控件。布局 `<head>` 中放最小预渲染脚本设置初始主题，避免闪烁；脚本逻辑与客户端控制遵守同一存储键及取值约定。
3. `src/components/SiteNav.astro` 增加控制，`BaseLayout.astro` 加载预渲染脚本和客户端初始化。
4. `src/styles/global.css`、`src/styles/tools.css` 和必要的局部样式使用主题 token。Giscus 客户端监听主题变更。无需更新内容 frontmatter 或背景注册表。
5. 增加测试覆盖偏好解析、系统变化、存储失败、导航三态、初始主题、评论主题同步，以及静态页面主题入口；更新 README 的使用说明。

## 验收

运行主题相关测试、现有完整构建、Worker 验证与 TypeScript 检查。浏览器逐一检查首页、文章、专题、搜索、六个工具和评论区的浅/深模式；至少覆盖宽屏与 390px 手机、系统外观变化、刷新保持、键盘操作、减少动态效果。无 JS 时默认浅色阅读层仍可阅读。完成后提交独立 PR，由用户合并发布。
