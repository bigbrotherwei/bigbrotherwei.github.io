# 第五阶段：实用工具设计

## 1. 阶段目标

把 `/tools` 从占位入口升级为可以日常使用的纯前端工具箱。第一批实现 JSON、Base64、URL、时间戳、UUID 和字数统计六个工具，并保持博客现有的手绘农场暮景视觉。

这一阶段不引入账号、后端、数据库、上传服务或大型前端框架。用户输入只在当前浏览器页面中处理，不发送到服务器，也不写入持久化存储。

## 2. 第一批范围

新增路由：

- `/tools/json/`
- `/tools/base64/`
- `/tools/url/`
- `/tools/timestamp/`
- `/tools/uuid/`
- `/tools/text-counter/`

工具首页 `/tools/` 启用搜索和分类筛选，并把当前占位卡片替换成真实工具入口。文本 Diff、Markdown、Mermaid、正则测试以及文件类工具不进入本阶段。

## 3. 信息架构

新增统一工具清单 `src/data/tools.ts`，每个工具包含：

- `slug`：路由和稳定标识。
- `title`：中文名称。
- `description`：一句话用途。
- `category`：文本、编码、时间或开发。
- `keywords`：供首页搜索。
- `backgroundKey`：工具详情页独立背景。

工具首页从清单生成卡片、分类和搜索索引，避免页面内容与路由定义分别维护。每个工具使用独立 Astro 页面，以便按照任务需要组织不同控件，同时共享工作台组件和样式。

## 4. 代码边界

工具逻辑放在 `src/lib/tools/`，保持为无 DOM 依赖的纯函数：

- `json.ts`
- `base64.ts`
- `url.ts`
- `timestamp.ts`
- `uuid.ts`
- `text-counter.ts`

页面交互只负责读取输入、调用纯函数、渲染结果和错误。通用页面结构由 `ToolLayout.astro` 提供，包括返回工具箱、标题、隐私说明和工作区容器；复制、清空、交换等命令使用一致的按钮状态和反馈。

不建立万能表单配置引擎。六个工具的输入结构并不相同，强行配置化会增加理解和维护成本。

## 5. 交互设计

工具详情首屏直接呈现可操作工作台，不放营销介绍。桌面端优先使用左右输入输出布局，窄屏改为纵向排列。工作台是一个完整工具面板，不在卡片中继续嵌套卡片。

通用状态：

- 初始状态提供简短占位提示。
- 输入发生变化时即时计算；高频文本输入使用轻量防抖。
- 可恢复错误显示在相关输入旁，不使用弹窗。
- 复制成功在按钮附近显示短暂状态，并兼容剪贴板 API 不可用的情况。
- 清空是即时操作，不弹确认框，因为内容未持久化且可重新输入。
- 所有按钮可用键盘操作，焦点样式清楚，状态信息使用 `aria-live`。

工具首页搜索按标题、描述和关键词进行大小写不敏感匹配；分类使用分段式筛选，搜索和分类共同生效。无结果时显示明确空状态。

## 6. 六个工具行为

### JSON

- 支持校验、两空格格式化和压缩。
- 成功时显示“JSON 有效”和转换结果。
- 失败时保留原输入，并显示解析错误，不覆盖上一次输入。
- 只处理标准 JSON，不接受注释、尾逗号或 JavaScript 对象字面量。

### Base64

- 支持 UTF-8 文本编码和 Base64 解码。
- 正确处理中文和 emoji，不直接依赖只支持 Latin-1 的 `btoa`/`atob` 输入方式。
- 解码非法内容时显示错误，不输出替代字符冒充成功结果。
- 提供编码/解码模式切换和输入输出交换。

### URL

- 使用 `encodeURIComponent` 和 `decodeURIComponent` 处理 URL 组件。
- 页面明确标注处理的是参数值或路径片段，不把完整 URL 的结构字符全部编码。
- 对不完整百分号序列给出错误提示。

### 时间戳

- 输入 Unix 秒或毫秒时间戳，按位数和值自动识别，也允许手动切换单位。
- 输出本地时间、UTC ISO 时间、秒时间戳和毫秒时间戳。
- 提供“现在”按钮写入当前时间。
- 对非数字、超出 JavaScript Date 范围或无效日期显示错误。

### UUID

- 使用 `crypto.randomUUID()` 生成 UUID v4，不使用伪随机降级实现。
- 一次生成 1 至 20 个，默认 1 个。
- 支持重新生成、逐项复制和复制全部。
- 浏览器不支持安全随机 UUID 时显示能力不可用，而不是返回低质量标识。

### 字数统计

- 即时统计字符数、去空白字符数、中文字符数、英文单词数、行数和 UTF-8 字节数。
- 空输入的行数为 0；末尾换行不额外虚增一个可见内容行。
- 英文单词按连续字母或数字词组统计，中文字符单独计数，避免用空格切分冒充中文“词数”。

## 7. 视觉与背景

六个工具详情页分别新增原创场景，保持蓝调暮色、暖色灯光、手绘细节和轻微游戏美术质感：

- JSON：档案整理室。
- Base64：编码电报小屋。
- URL：山谷路标与邮驿站。
- 时间戳：钟表工坊。
- UUID：温室种子编号台。
- 字数统计：抄写员书房。

每个场景提供桌面 WebP 和移动端裁切图，在 `src/data/backgrounds.ts` 中使用唯一 key 注册。背景不能与现有栏目、文章、专题或其他工具复用。

工作台使用低透明度纸张色面板，以可读性和连续操作效率为先。标题尺寸服从工具界面密度，不使用首页级超大字号。按钮优先使用熟悉图标配合文字或工具提示，不添加纯装饰动画。

## 8. 隐私、安全与错误处理

- 页面固定说明“内容仅在当前浏览器处理，不会上传”。
- 工具代码不发送网络请求，不记录输入，不写入分析事件内容。
- 输出通过表单值或文本节点更新，不使用用户输入拼接 `innerHTML`。
- 大输入不主动截断；超过合理体量时显示性能提示，并通过防抖避免每次按键进行重复重计算。
- 所有可预期错误返回结构化结果，由页面统一显示；编程错误仍抛出，避免静默失败。

## 9. 测试与验收

新增 `npm run verify:tools`，使用 Node 内置测试能力覆盖纯函数，不增加测试框架依赖。至少覆盖：

- JSON 合法、非法、格式化和压缩。
- Base64 中文、emoji、空值和非法输入。
- URL 中文、保留字符和错误百分号序列。
- 秒/毫秒时间戳识别、UTC 输出和非法范围。
- UUID 格式、数量边界和缺少安全 API。
- 字符、空白、中文、英文单词、换行和 UTF-8 字节统计。

构建校验需要确认六个路由存在、工具首页引用统一清单、每个工具使用唯一背景，并把 `verify:tools` 纳入现有 `verify` 和 `build`。

浏览器验收覆盖桌面和移动端：搜索、分类、转换、错误、复制、长文本、空状态、键盘焦点、背景裁切和文本溢出。完成后创建目标为 `master` 的独立 PR，不再以其他未合并功能分支作为目标。

## 10. 完成标准

- 六个工具均可通过导航进入并完成核心任务。
- 工具首页搜索和分类可组合使用。
- 用户输入不会离开浏览器。
- 六个详情页拥有互不重复的响应式背景。
- 自动测试、Astro 类型检查和静态构建全部通过。
- 桌面和移动端没有遮挡、溢出或不可操作控件。
