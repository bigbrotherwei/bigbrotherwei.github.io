# 第十三阶段：全站体验与性能整理

## 目标

在不改变现有手绘夜景风格、栏目结构和发布方式的前提下，降低背景加载时的空白感，检查窄屏阅读与键盘操作，并使每次发布都有可重复的验收步骤。继续使用 Astro 静态构建和 GitHub Pages，不增加运行时后端或访客追踪。

## 当前基线

- 各页面已配置独立的桌面和手机 WebP 背景，布局只预加载当前页对应视口的版本。
- 背景素材校验已有 350 KiB 上限；本地最大单张背景约 344 KiB，不能仅凭文件大小判断它是加载缓慢的原因。
- 本地 320px 宽度抽查首页、文章列表、专题列表、工具列表、FoundationDB 文章和 Markdown 工具，没有横向页面溢出。此项不代表其他视口、深色模式和键盘操作均已通过。
- 评论和统计依赖外部服务；外部服务不可用不得阻断静态内容展示。

## 实施范围

### 1. 背景加载

选首页、文章详情、专题详情和工具详情作为代表页面，在桌面和手机宽度记录背景文件、传输大小、是否只请求匹配视口的一张图，以及从页面开始加载到背景可见的时间。至少对首次访问和浏览器缓存后的访问各检查一次。若发现重复请求、首屏长时间纯色、解码卡顿或明显的慢图，先定位到素材或加载链路，再做针对性修改，并记录修改前后同条件结果。保留每页独立背景，不把手绘图改成简单色块。

### 2. 移动端与可访问性

覆盖 320px、390px 和常见桌面宽度，抽查首页、文章、专题、搜索和工具的首屏及主要交互。检查水平溢出、导航遮挡、正文/代码/表格可读性、可点击区域、键盘焦点、图标名称和减少动态效果设置。修复确认的问题，不进行无关的视觉重设计。

### 3. 发布巡检

保留现有 `npm run build` 作为合并前门槛。补充精简的中文上线清单：Pages 构建状态、首页与各类详情背景、搜索索引、RSS/站内链接、评论与统计的可用/降级状态。可由构建产物可靠判断的项目写入自动校验；必须依赖浏览器或外部配置的项目保留人工验收，避免假阳性。

## 交付顺序

1. 基线记录与背景加载的针对性优化，单独 PR。
2. 窄屏与键盘验收中发现的问题，按影响范围拆为小 PR。
3. 发布巡检清单及必要的自动校验，最后一个 PR。

每个 PR 都从当时最新的 `master` 创建；首页统计去框 PR #36 合并后，再合并本阶段的功能 PR，避免发布顺序混乱。

## 完成标准

- 代表页面的背景在对应视口正确显示，无桌面/手机版本双重加载；若有实际优化，附同条件前后对比。
- 抽查页面在目标宽度下无页面级水平溢出或导航遮挡，主要功能可用键盘操作，减少动态效果设置生效。
- 完整构建通过，发布清单能区分代码问题、Pages 部署问题与外部评论/统计配置问题。

## 不包含

不新增栏目、工具、管理后台、动画或第三方监测服务；不批量重画背景，也不为了压缩指标牺牲画面辨识度。
